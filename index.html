📡 Adaptive Sampling via Motion Entropy Tier 1
Why it matters

Interviewers ask "why 2 seconds?" — you now have a real answer: it's not fixed, it adapts. High motion → sample faster. Static scene → slow down. This is a smarter algorithm, not a parameter tweak.

  • Frame differencing: diff = abs(frame_t - frame_{t-1}). Sum pixel deltas → motion_score.
  • Entropy calculation: Compute Shannon entropy of the diff histogram. High entropy = lots of change.
  • Sampling interval: Map entropy → interval (e.g. 0.2s–3.0s). Use exponential moving average to smooth.
  • Skip logic: If time_since_last_sample < interval, pass frame through without full inference.
  • Log the interval: Write sample_interval_ms to every SQLite event row (Phase 3) for benchmarking.
import numpy as np from scipy.stats import entropy as sp_entropy def motion_entropy(prev, curr): diff = cv2.absdiff(prev, curr) hist = np.histogram(diff.flatten(), bins=64, range=(0,256))[0] hist = hist / hist.sum() + 1e-9 # normalise return float(sp_entropy(hist)) # 0 = static, ~4 = chaotic def adaptive_interval(entropy_val, lo=0.2, hi=3.0): # low entropy → long interval (save CPU), high entropy → short ratio = np.clip(1.0 - entropy_val / 4.0, 0, 1) return lo + ratio * (hi - lo)

🔄 FocusFSM State Engine Core
  • States: IDLE → FOCUSED → DISTRACTED → BREAK. Map all valid transitions with time thresholds.
  • FocusFSM class: update(focused: bool) → str. Cooldown timers prevent flicker (min 1.5s in state before transition).
  • Session tracker: Accumulate focused_s, distracted_s, break_s per session.
  • Alert system: Distracted >30s → system notification + optional audio beep. Pomodoro break reminder at 25 min.
class FocusFSM: STATES = ["IDLE", "FOCUSED", "DISTRACTED", "BREAK"] def __init__(self, cooldown=1.5): self.state = "IDLE" self.cooldown = cooldown self.last_transition = time.time() self.distracted_since = None def update(self, focused: bool) -> str: now = time.time() if now - self.last_transition < self.cooldown: return self.state # hold, don't flicker # ... transition logic ... return self.state
🍎 macOS Accessibility API Integration Tier 1
Why it matters

This is genuine OS-level programming. Almost no student portfolio touches the Accessibility API. Interviewers at Apple, Google, and systems-heavy companies go wide-eyed when you mention it.

  • Install pyobjc: pip install pyobjc-framework-Cocoa pyobjc-framework-ApplicationServices.
  • Frontmost app detector: Poll NSWorkspace.sharedWorkspace().frontmostApplication() every 5s → get bundle ID + name.
  • Context rules: Typing in VSCode → reduce sensitivity (–30% threshold). Idle on YouTube → increase it (+40%).
  • Typing detection: Use CGEventTapCreate to count keystrokes/min without reading content (privacy-safe).
  • Log app context: Write frontmost app + keystroke rate to SQLite alongside every detection event.
from AppKit import NSWorkspace def get_frontmost_app() -> str: ws = NSWorkspace.sharedWorkspace() app = ws.frontmostApplication() return app.bundleIdentifier() if app else "unknown" # Example context-aware threshold adjustment CONTEXT_THRESHOLDS = { "com.microsoft.VSCode": {"yaw_deg": 28}, # coding → relax "com.google.Chrome": {"yaw_deg": 15}, # browsing → strict }
🗄️ Structured Logging + SQLite Session Store Tier 1
Why it matters

Shows you think about data persistence, observability, and debugging. It's the difference between a script and a daemon. The real data also gives you charts to put in your write-up.

  • Schema: sessions table (id, start_ts, end_ts, focus_pct, score) + events table (ts, state, confidence, yaw, pitch, app_bundle, sample_interval_ms, false_positive).
  • Write path: Every FSM state transition + every sampled frame event → atomic INSERT.
  • CLI report command: focuslock report --today → prints session table to terminal. --week for weekly stats.
  • False positive flag: User can press f during session to mark last event as false positive → feeds back into threshold calibration.

🎯 Focus Score Algorithm (0–100) Tier 2
Why it matters

You're doing signal processing on behavioral data, not just detection. Adds a data engineering angle to the CV project — makes it three domains instead of two.

  • Score formula: FocusScore = 100 × (focused_s / total_s) × recovery_factor × fp_penalty.
  • Recovery factor: Reward fast return-to-focus after a distraction (short recovery time → higher score).
  • False positive penalty: Use user-flagged false positives from SQLite to downweight noisy sessions.
  • Display: ASCII bar chart in terminal at session end. Show score trend over last 7 days from SQLite.
